# RealEstate
RealEstate is a backend REST API built with ASP.NET Core 8 that provides a complete property listing and management system for real estate agencies. The solution follows Clean Architecture principles, keeping business logic completely isolated from infrastructure concerns. It is organized into four projects: Domain, Application, Infrastructure, and API, each with a clearly defined responsibility.
The Domain layer contains six core entities: Property, Listing, Agent, Client, Inquiry, and AppUser. A Property represents a physical real estate unit with attributes like area, floor count, bedroom and bathroom count, property type, and amenities such as parking and garden. A Listing connects a Property to an Agent, assigns a price and listing type (Sale or Rent), and tracks its current status through an Active → Sold/Rented/Withdrawn lifecycle. An Inquiry is created when a Client expresses interest in a Listing, and an Agent can respond to it directly through the API. The Domain layer also defines all repository interfaces, ensuring that the Application layer depends only on abstractions.
The Application layer holds four service classes — PropertyService, AgentService, ClientService, and ListingService — along with their corresponding interfaces and DTOs. The Result and Result<T> wrapper pattern is used consistently across all services to return either data or a descriptive error message without throwing exceptions. DTOs are separated per feature folder, keeping concerns organized and making it easy to evolve each contract independently.
The Infrastructure layer implements all repository interfaces using Entity Framework Core with SQL Server. All six repositories are implemented in a single structured file for clarity, each following the same async pattern. The AuthService in this layer handles JWT token generation and BCrypt password hashing. Entity relationships and constraints — such as unique email indexes, decimal precision for price columns, and cascade delete rules — are configured explicitly in the DbContext using the Fluent API.
The API layer exposes five controller groups: Auth, Properties, Agents, Clients, and Listings. Property and Listing search endpoints are intentionally marked as AllowAnonymous so that public users can browse available listings without authentication. All write operations require a valid JWT Bearer token, and administrative actions such as creating or deleting agents are restricted to the Admin role. Swagger UI is available in development mode with full Bearer token support for testing protected endpoints. To run the project, execute dotnet restore, apply EF Core migrations with dotnet ef migrations add and dotnet ef database update, then start the API with dotnet run.
